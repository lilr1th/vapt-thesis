[N-007] MEDIUM — Unauthenticated JWT Token Issuance
----------------------------------------------------
URL      : GET https://neuralsh.com/web/v1/init/token
CVSS     : 5.3 (AV:N/AC:L/PR:N/UI:N/S:U/C:L/I:N/A:N)
Status   : Confirmed + Exploited

Description:

  a signed JWT token with type "guest". No authentication,
  API key, or identifying information is required.
  Token lifespan: 30 minutes.

  Token decoded:
  Header:  {"alg":"HS256","typ":"JWT"}
  Payload: {"type":"guest","tid":"<uuid>","iat":<time>,"exp":<time+1800>}

Impact:
  The guest token grants access to the API base. Privilege levels
  exist (guest vs higher roles). If JWT secret is weak, tokens
  can be forged with elevated privileges (e.g. type:"admin").
  JWT secret cracking was attempted — not cracked with common wordlist.

Remediation:
  Require device fingerprint or app attestation before issuing tokens.
  Implement token binding to prevent token reuse across clients.
  Use a strong random JWT secret (32+ bytes).

[EXPLOIT-001] CRITICAL — Rate Limit Bypass via X-Forwarded-For Header
-----------------------------------------------------------------------
Finding  : N-005 (upgraded to Critical after exploitation)
Endpoint : GET /web/v1/init/token
CVSS     : 9.1 (AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H)

Proof of Concept:
  Without bypass: ~18 tokens before 429 rate limit triggered
  With bypass   : 50/50 tokens collected without any 429 response

  Command:
  curl -H "X-Forwarded-For: <random_ip>" \
       -H "X-Real-IP: <random_ip>" \
       https://neuralsh.com/web/v1/init/token

  Result: Rate limiting is based on X-Forwarded-For header value,
  not actual client IP. By spoofing a different IP per request,
  an attacker can generate unlimited valid JWT tokens.

Impact:
  - Unlimited token farming enables large-scale API abuse
  - Can be combined with automated brute force of authenticated endpoints
  - Bypasses all rate limiting protections on any endpoint
    that relies on the same IP-tracking mechanism
  - Enables credential stuffing and enumeration attacks at scale

Remediation:
  Use real client IP (behind Cloudflare: CF-Connecting-IP header)
  NOT X-Forwarded-For which is attacker-controlled.
  In Cloudflare: use CF-Connecting-IP for rate limiting.
